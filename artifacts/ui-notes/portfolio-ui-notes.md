# یادداشت UI صفحه دارایی / پرتفوی

## وضعیت فعلی

صفحه پرتفوی محل نمایش و مدیریت دارایی‌های کاربر است. این صفحه در نسخه فعلی شامل کارت ارزش کل دارایی، چارت ترکیب دارایی، لیست دارایی‌های صندوقی، سود/زیان، سرمایه‌گذاری مجدد و اطلاعات تکمیلی هر صندوق است.

## نقش صفحه

پرتفوی نباید تکرار داشبورد باشد.

داشبورد برای خلاصه وضعیت و اقدام سریع است.
پرتفوی برای مدیریت دارایی واقعی کاربر است.

## هدف بازطراحی UI-only

هدف، تبدیل صفحه پرتفوی به یک صفحه موبایل‌محور، قابل اسکن و عملیاتی است؛ بدون تغییر در سرویس‌ها، API، احراز هویت، پرداخت، سجام، روت‌ها یا منطق واقعی کسب‌وکار.

## ساختار پیشنهادی

- هدر کوتاه صفحه
- خلاصه ارزش کل دارایی
- ترکیب دارایی
- کارت مستقل برای هر دارایی
- عملیات هر دارایی: سرمایه‌گذاری بیشتر، برداشت، تبدیل
- نمایش سود/زیان به زبان ساده
- نمایش وضعیت سرمایه‌گذاری مجدد، در صورت وجود
- حالت خالی با دعوت به مشاهده صندوق‌ها یا شروع سرمایه‌گذاری

## اصول طراحی موبایل

- کارت‌ها یک‌ستونه و قابل اسکن باشند.
- جدول چندستونه در ویو موبایل استفاده نشود.
- عملیات اصلی روی هر دارایی قابل لمس و واضح باشد.
- اطلاعات ثانویه مثل جزئیات سود، آخرین درخواست و سرمایه‌گذاری مجدد پایین‌تر از مبلغ اصلی قرار بگیرند.
- صفحه از داشبورد متمایز باشد و نقش مدیریت دارایی داشته باشد.

## خط قرمزها

- تغییر سرویس‌ها ممنوع است.
- تغییر API ممنوع است.
- تغییر منطق پرداخت، احراز هویت، سجام و روت‌گارد ممنوع است.
- دامی‌دیتا فقط در سطح کامپوننت و برای پیش‌نمایش UI مجاز است.
