# فرضیات پروژه

## فرض ۱: حفظ عادت کاربران فعلی

آی‌پاسارگاد کاربر فعال دارد. بنابراین تغییرات نباید باعث سردرگمی کاربران فعلی شود.

### نتیجه طراحی

- جایگاه مسیرهای اصلی نباید ناگهانی تغییر کند.
- نقاط شروع جرنی‌های اصلی باید حفظ شوند.
- دکمه‌های اصلی مثل سرمایه‌گذاری، برداشت و تبدیل نباید از دسترس خارج شوند.
- تغییرات باید بیشتر در سلسله‌مراتب، چیدمان، خوانایی و وضوح انجام شوند.

---

## فرض ۲: تمرکز روی لایه نمایش

در فاز فعلی فقط روی لایه نمایش کار می‌کنیم.

### مجاز

- HTML
- SCSS / CSS
- متن‌های نمایشی
- چیدمان کارت‌ها و سکشن‌ها
- منطق نمایشی سبک داخل کامپوننت
- دامی‌دیتا برای پیش‌نمایش UI

### غیرمجاز

- تغییر سرویس‌ها
- تغییر API
- تغییر احراز هویت
- تغییر پرداخت
- تغییر سجام
- تغییر روت‌گاردها
- تغییر اینترسپتورها
- تغییر منطق واقعی کسب‌وکار

---

## فرض ۳: موبایل‌محور بودن تجربه

آی‌پاسارگاد باید با اولویت تجربه موبایل تحلیل، مستندسازی و بهبود داده شود.

### نتیجه طراحی

- ویو اول هر صفحه باید برای صفحه موبایل طراحی شود.
- نوار پایین، دکمه‌های اصلی و کارت‌های عملیاتی باید با thumb zone و استفاده یک‌دستی هماهنگ باشند.
- اطلاعات مهم باید در ارتفاع قابل مشاهده موبایل قرار بگیرد.
- هر صفحه باید اسکرول‌پذیر، سبک، قابل اسکن و بدون تراکم زیاد باشد.
- طراحی دسکتاپ یا تبلت نباید مبنای تصمیم‌گیری اصلی باشد.
- اگر فضای صفحه محدود است، اولویت با عملیات اصلی و وضعیت‌های فوری است.
- فیچرهای جانبی باید پایین‌تر از ویو اول یا در صفحه بیشتر / پروفایل قرار بگیرند.

---

## فرض ۴: جداسازی نقش منوهای اصلی

هر آیتم نوار پایین باید منطق مشخص داشته باشد:

- داشبورد: خلاصه وضعیت، هشدارها و اقدام سریع
- صندوق‌ها: کشف، بررسی و ورود به عملیات صندوق
- دارایی / پرتفوی: مدیریت دارایی کاربر
- گزارش‌ها: تاریخچه، رسیدها و پیگیری درخواست‌ها
- بیشتر / پروفایل: تنظیمات، امنیت، پشتیبانی و امکانات جانبی

---

## فرض ۵: فیچرهای جانبی نباید با عملیات اصلی رقابت کنند

امکاناتی مثل کارت بانکی آی‌پاسارگاد، سرمایه‌گذاری خودکار و پرداخت مستقیم باید در دسترس باشند، اما نباید در ویو اول داشبورد با عملیات اصلی رقابت کنند.

### جای مناسب

- بخش پایین‌تر داشبورد
- صفحه بیشتر / پروفایل
- لحظه‌های مناسب در مسیر کاربر
